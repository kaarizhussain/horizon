## The core call

For weeks the roadmap has been feature-forward — habits, estimates,
deep-work protection, digests, always-on — and all of it shipped. But the
loop it exists to serve (**goals → plan → execute → learn**) has never run on
your real goals for even a week. The highest-leverage next move is not
another feature. It's to **ship the redesign, put your real life into it, and
let a week of actual use decide what's next.** That is also the only honest
way to hit your own bar ("remove real manual work") — you can't see the
manual work until you're the user.

## Risks
- **Builder trap** — shipping features is more satisfying than using the
  product; the discipline is to use the thing instead.
- **Doc/reality drift** — already happened once; M0 step 1 is the guard.
- **Single-tenant vs. portfolio ambiguity** — keeps making "is X worth it?"
  calls fuzzy. Name it: personal tool that *could* become a portfolio piece —
  so stay multi-tenant-safe, but don't build platform features yet.
- **Unsupervised automation cost** — M3's always-on planning is recurring
  Claude API spend running without you watching; arm it deliberately, not by
  default.
